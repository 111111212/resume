PythonFastAPILangGraphMCP SQLAlchemyMySQLBM25PGVector SSEDeepSeek / Qwen API
  • 基于 LangGraph 搭建 Supervisor 中心调度的状态图：三类专家 Agent 执行完统一回流 Supervisor 重新决策，由此支持按需路由、SQL 报错后带错误信息重写重试、检索不足时补充检索；用 Checkpointer 按 thread_id 保存节点状态，人工审批挂起后可原地恢复，不必重跑前面的步骤。
  • 实现 Agentic RAG：不写死「先检索再回答」的固定流水线，由 Agent 判断本轮是否需要查口径、结果是否够用；检索侧用 BM25 词法召回 + 同义词扩展（GMV／销售额、退款率／退货率等），向量通道（PGVector）按环境变量可插拔、未配置时自动退化为单通道，两路经 RRF 融合后按「标题命中 + 关键词覆盖」规则重排，使「销售额怎么算」这类问法稳定命中对应口径切片。
  • 做上下文工程：按问题裁剪 Schema、只注入相关表字段，对工具返回做截断与结构化压缩，历史会话只保留 3 轮滚动摘要，在保证准确率的前提下压低单轮 token 与首字延迟。
  • 按 MCP 协议将 SQL 执行器、指标字典、图表生成分别封装为 3 个独立 MCP Server，Agent 侧以 MCP Client 统一注册调用；SQL 落地前统一过 7 层校验（只读强制、多语句堆叠拦截、只读语句内藏写操作检测、表白名单、自动补 LIMIT、全表扫描转人工确认等），写操作与高危查询经 interrupt 触发 Human-in-the-loop，审批通过后从断点继续执行；输入侧做 Prompt 注入特征检测，并对工具参数逐字段扫描。
  • 自建 Text2SQL 评测脚本：以「执行结果与基准 SQL 结果逐列比对」为判定标准，统计生成成功率与结果准确率，用于迭代提示词与路由策略；同时保留无 API Key 时自动降级到规则引擎的能力，离线也能完整跑通链路与页面。
